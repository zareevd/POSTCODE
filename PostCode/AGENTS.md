# Правила работы с проектом

## Контекст

Прототип подписки для хакатона ПочтаТеха, команда из двух человек. Официальное ТЗ получено 24.11.2026; источник — docs/requirements-2026-11-24.md. Не выдавать гипотезы о тарифах и привилегиях за требования организатора.
В `sites/pochtatech-premium` есть статическое демо подписки; локальное приложение запускается командой python run.py. Для изменений демо читать его `DESIGN.md` и
сохранять существующий Site ID и приватный доступ.

## Перед задачей

- Прочитать `docs/handoff.md` и релевантные разделы `docs/scope.md`.
- Проверить `git status`; сохранять чужие незавершённые изменения.
- Смотреть только нужные файлы, не загружать весь репозиторий в контекст.
- Определить результат задачи и критерий готовности.

## Реализация

- Делать небольшие законченные изменения в существующей структуре.
- Не устанавливать стек и зависимости до задачи на инициализацию приложения.
- Использовать ветки `codex/<короткое-название>` для новых задач.
- Согласовывать общие типы и операции через `docs/contracts.md`.
- Бизнес-правила держать в `src/server/services`, доступ к данным — в
  `src/server/repositories`, внешние API и имитации — в `src/server/integrations`.
- Не делать дополнительные сервисы, очереди и AI-функции без требования задачи.
- Обозначать имитации и использовать синтетические демонстрационные данные.
- Не публиковать секреты, `.env` и локальные базы данных.
- Не запускать дополнительных агентов без явного запроса пользователя.

## Ресерч и экономия контекста

- Сначала проверять `docs/research.md`, затем искать недостающую информацию.
- Для текущих фактов использовать первоисточники и фиксировать дату проверки.
- Для API библиотек сверять документацию с выбранной версией зависимости.
- Возвращать нужные фрагменты, а не полные страницы и журналы команд.
- Отделять проверенные факты от гипотез и оставшихся вопросов.

## Завершение

- Выполнять проверки, соразмерные изменению; для документов — ссылки и diff.
- После появления приложения поддерживать реальные команды проверок в README.
- Не утверждать, что сборка или тесты прошли, если их не запускали.
- Обновлять `docs/handoff.md`: готово, следующий шаг, препятствия, проверки.
- Кратко сообщать результат и существенные ограничения.
