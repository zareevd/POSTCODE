# Архитектура локального MVP

Python обслуживает HTTP-формы и JSON API, формирует HTML на сервере и хранит данные в SQLite. Для старта требуется одна команда без установки библиотек. См. [устройство прототипа](technical-documentation.md).

# Архитектура

## Принятые решения

- Один репозиторий, одно приложение.
- UI, бизнес-правила и доступ к данным разделены по ответственности.
- Реальные интеграции и имитации используют общие контракты.
- Визуальная демонстрация размещена отдельно в `sites/pochtatech-premium`:
  статические HTML/CSS/JS без зависимостей и шага сборки. Это не выбор стека
  полноценного приложения; его выбор остаётся отдельной задачей инициализации.

## Границы модулей

- `src/app`: маршруты, страницы и транспортные обработчики.
- `src/features`: интерфейс и клиентская логика отдельных возможностей.
- `src/components/ui`: переиспользуемые визуальные компоненты.
- `src/server/services`: правила подписки, расчёты и применение привилегий.
- `src/server/repositories`: чтение и сохранение данных.
- `src/server/integrations`: обращения к сторонним системам и их имитации.
- `src/shared`: общие типы без серверных секретов и зависимостей.
- `db`: миграции и синтетические данные после выбора хранилища.

Не импортировать серверные модули в клиентские компоненты.
